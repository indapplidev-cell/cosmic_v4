Cosmic Game Rules
1) Goal

Control the ship on a tile-based track and survive as long as possible.

Your score grows as you progress (distance/progress).

Record is the maximum score across all attempts.

2) Controls
On smartphone (Android)

← Left: move the ship to the left

→ Right: move the ship to the right

↓ Brake: slows forward movement speed (easier to maneuver)

Button behavior:

Short tap on ←/→ = one step (discrete shift).

Hold ←/→ = smooth movement in the selected direction.

Hold ↓ = braking; release returns normal speed.

On PC (if the game is launched there)

Arrow keys ←/→ for movement, ↓ for braking.

3) Score and Record

Score is your result in the current run.

Record is updated if the current result is higher than the previous one.

Record is fixed at the end of the run/when exiting the game screen (to avoid "accidental" updates).

4) Lives (attempts)

Each game session has 3 lives.

A life is lost on a mistake (for example, leaving the track/collision).

After losing a life:

if lives still remain, a soft reset happens (the ship returns to a safe position), and the game continues;

if lives are over, Game Over occurs.

5) Extra Lives

After Game Over, you can continue:

tap "Get" and complete a rewarded scenario (ad/reward action),

after that, lives are restored to 3 and the game continues.

Important: each "revive" is treated as an advantage and is reflected in rating (see below) through spent lives/efficiency.

Rating, balance, payouts
6) Rating

Rating is formed from game session results and affects profitability.

Rating calculation includes:

Record/best result (higher is better)

Completion time (faster/more efficient point gain is better)

Number of spent lives (fewer is better)

Anti-abuse/validity:

Only valid starts are counted: an attempt is counted if the player survived at least ~9 seconds.

Frequent instant restarts do not improve rating.

7) Balance

Balance is credited after the game session ends.

Balance depends on rating: the higher the rating, the higher the session credit.

Basic crediting logic:

Balance increases by a value that depends on Rating.

The more lives are spent (and the more frequent continuations), the lower the final efficiency -> lower rating -> lower credit.

8) Payouts

Payouts are available only when Balance is at least 100 units.

If Balance < 100, payout request is unavailable.

After reaching Balance >= 100:

the user can submit a payout request in the corresponding app section;

credits/payouts may be checked for result validity (anti-fraud).

9) Restrictions and Fair Play

Any boosting methods (mods, data substitution, click emulation, app interference) lead to:

credit cancellation,

payout blocking,

possible account blocking.
